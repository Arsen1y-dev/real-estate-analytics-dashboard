## 1. Требования дашборда

Источники: `README.md`, `src/domain/dataset.ts`, `shared/dashboard.ts`, `shared/filters.ts`, `ObjectsMap.tsx`, `FilteredListingsTable.tsx`, `SegmentComparison.tsx`.

### 1.1 Core-фильтры (`CoreColumnMap`)

| Функция | Колонка processed | Обязательность |
|---------|-------------------|----------------|
| Цена | `Цена` | Для KPI, пресетов, фильтра |
| Площадь | `Общая площадь` | То же |
| Комнаты | `Количество комнат` | Фильтр; fallback по имени колонки с «комнат» |
| Год постройки | `Год постройки` | Фильтр |
| Расстояние до центра | `Расстояние до центра (км)` | Фильтр; fallback — haversine по `Широта`/`Долгота` |
| Относительный этаж | `Этаж_относительный` | Фильтр этажа |
| Первый / последний этаж | `Первый_этаж`, `Последний_этаж` | Чекбоксы исключения |
| Тип дома | one-hot `тип_дома_*` → runtime `houseType` | Фильтр по типу |

### 1.2 Карта

| Поле | Колонка |
|------|---------|
| Координаты | `Широта`, `Долгота` |
| Подпись | `Адрес` (опц.) |
| Баллун: цена, комнаты | `Цена`, `Количество комнат` |

### 1.3 Таблица (analyst/admin)

Приоритет: `ID`, `Адрес`, `Ссылка` / `URL`, core-поля, `Широта`, `Долгота`.

### 1.4 Сравнение сегментов

| Поле | Логика |
|------|--------|
| `Возраст дома` | ≤ 3 → новостройка |
| `Год постройки` | запасной критерий |
| `Срок сдачи` | > 0 → новостройка (если год/возраст не сработали) |

### 1.5 Графики

- Числовые: любые столбцы с ≥85% числовых значений (`buildDataSummary`).
- Категориальные: one-hot `тип_дома_*`, `санузел_*`, `окна_*`, `ремонт_*`, `парковка_*`, `вид_сделки_*`, `способ_продажи_*`, флаги `*_есть`, `Двор_*`.
- Пресеты: `Цена`, `Общая площадь`, `Количество комнат`.

### 1.6 Идентификация

`ID`, `Адрес`, `Ссылка` — в `schema_contract.json` → `identity_columns`.

## 2. Колонки details CSV (парсер)

`DETAILS_FIELD_ORDER` в `yandex_realty_details_parser.py` (май 2026 — доработка Москвы):

```
Название, Заголовок карточки, Класс жилья, Тип объявления, Цена, Цена за метр, Адрес, Дата публикации,
Продавец, Тип продавца, ID объявления, Количество комнат, Общая площадь,
Жилая площадь, Площадь кухни, Этаж, Этажей в доме, Высота потолков, …
Название новостройки, Корпус, строение, Застройщик, Тип проекта, Подъезды, Охрана,
Вид сделки, Способ продажи, Тип участия, Срок сдачи, Дополнительно, Геолокация, Ссылка
```

**Исправления парсера (пилот offer `1008324627150474372`):**

| Проблема | Решение |
|----------|---------|
| Адрес «В экспозиции 7 д.» | Фильтр `looks_like_address`, проезд/проспект/Москва, JSON-LD, `<title>`, блок локации |
| Цена/м² 765388 vs 707806 | Парсинг «₽ за м²» с отсечением «Средняя цена ЖК», сверка с цена/площадь |
| Пустой ID при URL с `/` | `extract_offer_id`: regex `/offer/(\d+)` |
| Пустые комнаты при «4-комнатные» | `parse_rooms_from_text` в парсере + ETL `(\d+)\s*[-\s]*комнат` |
| Пустые этаж/жилая/потолки у новостроек | `collect_spec_pairs` + разбор текста «N этаж из M», «м² жилая» |
| Дата «Обновлено …» вместо «N мая, M просмотров» | `extract_publication_date` — `OfferCardSummaryHeader__text`, не `class*='date'` |
| Пустые парковка/тип дома за «ещё N характеристик» | `collect_offer_card_feature_titles` + `apply_about_house_features` (чипы `OfferCardFeature`) |
| Нет поля мусоропровод | Колонка **`Мусоропровод`** в `DETAILS_FIELD_ORDER` (details only, не в processed) |
| `headless: true` и капча | В `config.moscow.json`: **`headless: false`** (окно Chrome) |
| Hero ≠ краткий H1 | **`Заголовок карточки`** — полный маркетинговый заголовок; **`Название`** — строка с м²/комнатами |
| Сегмент (Элитный, Комфорт…) | **`Класс жилья`** из бейджей `OfferCardHighlight`/галереи |
| `Срок сдачи` обрезался до «3 кв» | Regex `_COMPLETION_TERM_RE` → полный текст «3 кв. 2027» |
| Футер в Тип проекта / Вид сделки | `is_polluted_text` + blacklist; корпус без «N из M Этаж» |
| Отделка / тип дома / парковка | Чипы summary + `OfferCardFeature` (полные строки, «Мусоропровода нет» → нет) |

**Параллельность:** не включена — один браузер, меньше риск капчи; ускорение за счёт resume и flush каждые 10 карточек.

## 4. Цепочка details → ETL → processed

| Dashboard (processed) | Источник details | Трансформация ETL |
|----------------------|------------------|-------------------|
| `ID` | `ID объявления` или URL в `Ссылка` | `extract_listing_id` |
| `Адрес`, `Ссылка` | одноимённые | строка |
| `Цена`, `Общая площадь`, `Жилая площадь` | одноимённые | `to_float` |
| `Количество комнат` | `Количество комнат` + `Название` | `parse_rooms` |
| `Год постройки`, `Срок сдачи` | одноимённые | `to_int` (срок: текст → часто 0) |
| `Широта`, `Долгота` | `Геолокация` `lat,lng` | `parse_geo` |
| `Расстояние до центра (км)` | — | haversine(`city_center` из config) |
| `Цена за м²`, `Возраст дома` | цена, площадь, год | вычисление |
| `Этаж_относительный`, `Первый_этаж`, `Последний_этаж` | `Этаж`, `Этажей в доме` | `parse_floor` |
| `санузел_*` … `способ_продажи_*` | `Санузел`, `Окна`, `Ремонт`, `Тип дома`, `Парковка`, `Вид сделки`, `Способ продажи` | `categories.py` one-hot |
| `Мебель_есть`, `Техника_есть`, лифты | `Мебель`, `Техника`, лифты | `bool_like` |
| `Двор_*` | `Двор` | подстроки «закрыт», «дет», «спорт» |

Поля парсера **не** идут в processed напрямую (доп. аналитика в details только): `Цена за метр`, `Площадь кухни`, `Высота потолков`, `Балкон`, `Отделка`, `Тёплый пол`, продавец, дата публикации и т.д.

### 5.2 Не блокируют дашборд

| Пробел | Комментарий |
|--------|-------------|
| Низкое заполнение `Количество комнат`, `Этаж`, `Ремонт`, `Тип дома` в details (Саратов) | ETL восстанавливает комнаты из `Название`; one-hot даёт хотя бы `*_другое` / `*_не указано` |
| `Срок сдачи` в details — текст («Сдан», «4 кв. 2027»), в processed всегда 0 | Сегмент «новостройки» опирается на `Возраст дома` / `Год постройки`; для Москвы желателен отдельный парсинг года из текста (улучшение ETL, не схема) |
| `ID объявления` в CSV часто пуст | ID берётся из URL — 100% в processed |
| `Грузовой лифт`, `Двор`, `Мебель` — редко в details | Фильтры/графики по ним опциональны |

### 5.3 Схема

Расхождений между `schema_contract.json`, ETL-выходом и `processed_apartment_data.csv` дашборда **нет** (56 колонок, diff пустой).

## 7. Готовность к `moscow-details`

**Да**, при условиях:

1. `data/moscow/yandex_realty_links.txt` — достаточно ссылок (цель ≥10k).
2. Активирован venv, `pip install -r requirements.txt`.
3. Запуск из корня `Kursach3` с `config.moscow.json` (`city_center` = Москва).

**Не запускать** полный прогон в рамках этого аудита (по запросу пользователя).

### Рекомендуемые команды после фиксации репозитория

```bash
cd /Users/arseniy/Documents/GitHub/Kursach3
source venv/bin/activate   # или путь к вашему venv
pip install -r requirements.txt

wc -l data/moscow/yandex_realty_links.txt   # проверка объёма ссылок

make moscow-details    # resume_details: true в config.moscow.json
make moscow-etl
make moscow-qa
make moscow-handoff    # → ../real-estate-analytics-dashboard/processed_apartment_data.csv

Опционально до длинного прогона — smoke на существующем details (если появится `data/moscow/yandex_realty_details.csv` с пилотной выборкой):

```

(уточнить target в `Makefile`, если smoke жёстко привязан к `config.json`.)
